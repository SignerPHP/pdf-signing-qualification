# RFC conformance

How this repository answers the RFC [Reproducible PDF Signing Qualification and Benchmarking for SignerPHP](https://github.com/SignerPHP/.github/blob/acb43d14a7758fe1257d3e87d621688bd60fce84/docs/rfcs/pdf-qualification-research-protocol.md), version 0.1 of 2026-10-10, as proposed in [SignerPHP/.github#3](https://github.com/SignerPHP/.github/pull/3) at commit `acb43d14a7758fe1257d3e87d621688bd60fce84`: each research question of section 4 and each requirement of sections 5 to 8, with the command, schema, analyzer or published report that answers it, and the parts left out or deferred, with who decided it, or that the decision is not recorded, and the issue that tracks it. The RFC itself is not edited here.

Each requirement has one status:

- **Met**: the repository does what the RFC asks, and the evidence shows it.
- **Partially met**: part of it is done; the note says what is missing.
- **Deferred**: not done yet, and kept for later work by a recorded decision.
- **Left out**: not done, and not kept for later work by any recorded decision; the note says what is known.

The state below is that of `main` after [#79](https://github.com/SignerPHP/pdf-signing-qualification/pull/79). The results that `docs/` cites are in releases [`results-20261110-1`](https://github.com/SignerPHP/pdf-signing-qualification/releases/tag/results-20261110-1), for the pilot results, the replay and the performance study, and [`results-20261128-1`](https://github.com/SignerPHP/pdf-signing-qualification/releases/tag/results-20261128-1), for the differential baseline and the PAdES scenarios, which replaces the bundles of [`results-20261127-1`](https://github.com/SignerPHP/pdf-signing-qualification/releases/tag/results-20261127-1) for both.

## Research questions (section 4)

| **RQ2**, functional qualification: which structure, signing and document-state categories go with supported behavior, expected rejection, failures or invalid outputs | Met | `run-attempts` and `report`, whose coverage matrix and verdicts are given by stratum; the [pilot results](pilot-results.md), the [differential baseline](differential-baseline.md), the [visible-appearance scenario](visible-appearance.md) and the [PAdES results](pades-scenarios.md#results-on-the-pilot-sample). | **RQ3**, independent verification: how consistently distinct verifiers judge structure, cryptography and preservation, and where they disagree | Met | The analyzers of the [schemas README](../schemas/README.md#semantics), the baselines of each input before signing, and the `validator_disagreement` class of `compare-implementations`; the causes of the disagreements are in the [differential baseline](differential-baseline.md#validator-disagreements) |
| **RQ4**, comparative performance: paired distributions of complete-process duration, CPU time and memory over eligible and independently valid cases | Partially met | `bin/performance` and `analyze-performance` under the [performance protocol](performance-protocol.md); the [performance results](performance-results.md), for `basic-invisible-sha256` on the main panel and one host, measured before later changes listed under section 6.7. | External-reference boundary: JSignPdf measured as a whole observable process, with child-process resource accounting as applicable, and no Java instrumentation or heap profiling | Partially met | Measurements have `instrumented: false` and the `process_tree` boundary, which holds the JVM ([performance protocol](performance-protocol.md#measured-boundary)). | Excluded: LibreSign or Nextcloud throughput | Met | Not measured; stated in the limits of the [performance protocol](performance-protocol.md#limits) and [results](performance-results.md#limits) |

The RFC itself asks for both, upstream acquisition in section 6.2 and JSignPdf in this section, so this repository reads the exclusion as forbidding unpinned dependencies: every input is fetched at an immutable revision and checked against its SHA-256, and every dependency of the [`Dockerfile`](../Dockerfile) is pinned by version, commit or SHA-256 |
| Excluded: malware classification and mandatory machine learning; paid remote AI services | Met | No analyzer of [`ValidationPanel`](../src/Validation/ValidationPanel.php) classifies malware or uses a model or a remote service |
| Excluded: indefinite retention of generated PDFs | Met | Signed outputs are never published or committed; they stay only in the local `var/` of whoever ran the command, which Git ignores ([what is never published](results-publication.md#what-is-never-published), [retention](results-publication.md#retention)) |
| Excluded: silent algorithm substitution | Met | Scenarios name the digest, signature algorithm and sub filter; the adapters pass them, `pdf-signer` with `--no-default-timestamp`, and a revision whose help does not list every option passed is `incompatible` ([schemas README](../schemas/README.md#semantics)) |
| Excluded: claims of comprehensive ISO or PAdES conformity | Met | Every report states its limits, such as those of the [differential baseline](differential-baseline.md#limits) |

| Requirement | Status | Evidence and notes |

| Dependent observations: capability, result, verdicts, errors, artifact hashes, duration, CPU and peak memory, with PHP-phase diagnostics reported apart | Partially met | [`v1/attempt.schema.json`](../schemas/v1/attempt.schema.json), [`v1/observation.schema.json`](../schemas/v1/observation.schema.json), [`v2/measurement.schema.json`](../schemas/v2/measurement.schema.json). | Controls: operating system, container, CPU, PHP and Java versions, lockfiles, isolation policy, temperature, cache and startup conditions, warm-up, certificate fixtures, local substitutes for external services | Partially met | `run.json` records the image id, operating system, PHP version, CPU model, limits and confinement, `harness` the commit of this repository and whether its working tree held files that differ from it, untracked files that are not ignored included, and `implementation_runtime` the Java version and options. ### 6.5 Execution isolation

| Requirement | Status | Evidence and notes |
| ----------- | ------ | ------------------ |
| Bounded time, memory, CPU, process count, files and temporary storage per attempt | Partially met | Wall time, enforced by the measuring process and the runner; address space, file size and open files with `prlimit`; CPU time and processes over the process tree ([#54](https://github.com/SignerPHP/pdf-signing-qualification/issues/54), [#68](https://github.com/SignerPHP/pdf-signing-qualification/pull/68)); and the storage of the `tmpfs` work directory; all in `resource_limits` ([AGENTS.md](../AGENTS.md#environment), [`ResourceLimits`](../src/Signing/ResourceLimits.php)). Missing: memory is bounded per process, 1 GiB of address space each, not per attempt; an attempt of up to 128 tasks is bounded as a whole only by the 3 GiB of the container ([`compose.yaml`](../compose.yaml)), which it shares with the runner, the validators and the test PKI server. Validator commands get the time limit of their adapter and the confinement, without `prlimit` bounds |
| No unrestricted network egress; no access to secrets | Met | The `sandbox` service has only loopback, and the runner refuses to start otherwise; each attempt runs with an empty environment ([AGENTS.md](../AGENTS.md#environment)) |
| No path traversal or unsafe archive extraction | Met | Identifiers reject `.`, `..` and empty segments ([schemas README](../schemas/README.md#semantics)); Landlock limits writes to the attempt's work directory; no input is an archive, and nothing a run reads is extracted |
| Child processes terminated on timeout | Met | [`docker/measure-process-tree.py`](../docker/measure-process-tree.py) is the subreaper of the attempt and kills its whole tree at the limit and when the command ends (*Measurement* in the [schemas README](../schemas/README.md#semantics)) |
| Disposable environments and least privilege | Met | A fresh work directory per attempt, no capabilities and `no-new-privileges`, and Landlock confinement of every attempt ([#53](https://github.com/SignerPHP/pdf-signing-qualification/issues/53), [#60](https://github.com/SignerPHP/pdf-signing-qualification/pull/60)) and of every validator command ([#59](https://github.com/SignerPHP/pdf-signing-qualification/issues/59), [#67](https://github.com/SignerPHP/pdf-signing-qualification/pull/67)). Landlock does not cover file metadata, and `/proc` stays readable, as the *Confinement* semantics of the [schemas README](../schemas/README.md#semantics) state |
| Test credentials never emitted in outputs | Met | Credentials and the test PKI are generated per run outside the results and removed afterwards; the password is redacted from kept errors, and records identify certificates by SHA-256 ([results publication](results-publication.md#exposure), [PAdES audit](pades-scenarios.md#audit-of-the-bundles)) |
| Network-dependent TSA and revocation behavior only by explicit opt-in, with controlled fixtures | Met | Only version 3 scenarios declare a timestamp or revocation data, and they use the run's [test PKI](pades-scenarios.md#test-pki) on loopback |

| Requirement | Status | Evidence and notes |
| ----------- | ------ | ------------------ |
| Process execution apart from capability and eligibility | Met | `execution.outcome` and `capability` of [`v1/attempt.schema.json`](../schemas/v1/attempt.schema.json), described under *Attempt* in the [schemas README](../schemas/README.md#semantics) |

| Prior-signature preservation and DocMDP constraints | Partially met | `qpdf-prior-signatures` and `qpdf-certification-permissions` ([#56](https://github.com/SignerPHP/pdf-signing-qualification/issues/56), [#71](https://github.com/SignerPHP/pdf-signing-qualification/pull/71)). | Visual or semantic preservation only in designed scenarios | Met | `pdftoppm-appearance`, only under [`basic-visible-sha256`](visible-appearance.md) ([#45](https://github.com/SignerPHP/pdf-signing-qualification/issues/45)) |
| Each observation names its analyzer, version, policy, artifacts, verdict and evidence | Met | [`v1/observation.schema.json`](../schemas/v1/observation.schema.json) |
| Distinct `valid`, `invalid`, `inconclusive`, `not_evaluated` and `not_applicable` | Met | *Verdict* in the [schemas README](../schemas/README.md#semantics) |
| No majority vote between verifiers | Met | Each analyzer writes its own observation; disagreements are reported as `validator_disagreement`; a boundary of [AGENTS.md](../AGENTS.md#boundaries) |
| A scan for PDF tokens is only a heuristic | Met | No verdict comes from such a scan; the comparing analyzers work on what qpdf parses and on exact byte or pixel comparisons, as the end of *Validators* in the [schemas README](../schemas/README.md#semantics) states |

### 6.7 Benchmark and statistical protocol

| Requirement | Status | Evidence and notes |
| ----------- | ------ | ------------------ |
| Paired comparison only over a common eligible population with equivalent configuration | Met | The eligibility rule of the [protocol](performance-protocol.md#question-and-population); `analyze-performance` refuses runs that differ in anything but the implementation |

| Repetitions, warm-up, order and counterbalancing, seeds and controls fixed from pilot evidence | Met | The [calibration](performance-protocol.md#calibration) and the [repetitions, warm-up, order and seeds](performance-protocol.md#repetitions-warm-up-order-and-seeds) |

| Paired distributions with medians, quantiles and uncertainty, the document as the unit | Met | [Statistics](performance-protocol.md#statistics) and [paired distributions](performance-results.md#paired-distributions) |
| No universal winner from unrepresentative samples | Met | [Performance results](performance-results.md#limits) |
| Optional PHP phase diagnostics with `hrtime()` and PHP memory APIs, apart from uninstrumented runs | Left out | Not built, and no issue tracks it. The RFC makes it optional, to be weighed after the process-level measurements; nobody has taken it up since, and no decision on it is recorded |

The measured sessions date from 2026-11-09. They were judged before [#50](https://github.com/SignerPHP/pdf-signing-qualification/issues/50), merged on 2026-11-11, which the [results](performance-results.md#coverage-of-the-whole-panel) account for. They also ran before changes inside the measured process, the Landlock confinement of the attempts ([#60](https://github.com/SignerPHP/pdf-signing-qualification/pull/60), merged on 2026-11-25) and the CPU time and process bounds that the measuring process enforces (#68), and before the confinement of the validators (#67) and the analyzer of #71, which run outside the measured boundary but take part in the eligibility. Running them again needs the controlled host; no issue tracks it.
